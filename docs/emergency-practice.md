# 校园疫情应急处置实训

更新时间：2026-11-06（Asia/Shanghai）。需求：让应急判断、报告、协同和后续处置在训练中可操作、可追溯。

## 学员流程

1. 首页说明训练目标，沿用已有情境与自定义设置、对话框和模型选择。学校日常健康填报属于应急准备；公开情境含突发异常线索时显示应急处置目标。
2. 进入实训后展示应急处置台。安全保护、核实信息、校内报告从开始即可填写，三项可并行推进，校内报告无需等待全部信息核实。
3. 学员选择处置思路，填写已知信息、待核事项、行动依据、责任分工、反馈节点。可关联最多3条本人教师发言。每次提交均为模拟决策记录。
4. 协同任务在2轮对话或协同阶段开放；家长沟通在4轮对话、既有传言事件或方案阶段开放；跟进在6轮对话或方案阶段开放。轮次是教学任务呈现安排，现实应急处置遵循当前学校预案。追加问题明确标为演练假设，情境事实仍以原版本及披露规则为准。
5. 方案阶段提示尚缺记录；进入评价后记录只读。处置选项反馈提示复核方向，文字方案需要结合情境审阅。正式五维评价保持原解析及证据校验。
6. 复盘呈现提交顺序、各环节方案、修订、遗漏和对话锚点。提交时间表示平台留痕，实际处置时间需要独立依据。新人指引自动导航到实训并定位处置台。

## 实现与边界

- `lib/training/emergency-plan.ts`：公共教学任务、可用性、记录汇总及评价上下文。
- `lib/training/emergency-service.ts`：既有账号事务、训练归属行锁、状态及证据校验、请求ID幂等和事件追加。
- `/api/training-practice/[id]/emergency`：认证账号读取与提交，写入要求同源JSON、16KiB请求上限。普通用户限自己的训练。
- `components/classroom/emergency-board.tsx`：首页概览、处置台和复盘，沿用紫色主题与现有Dialog。
- 无新表、迁移或情境版本更改；事件类型为`emergency-decision-recorded`，payload版本1。服务器记录不会改变核心训练阶段、隐私披露、模型路由或外部报告状态。
- 决策是学员输入资料；模型评价继续引用真实教师消息ID。模拟选择或文字承诺不作为已经联系、已经报告或已经完成医疗处置的证明。
- 既有训练历史可继续阅读；缺少新记录时明确显示未记录。情境及文献的既有ID与内容保留。

## 教学依据

- [教育部转发学校和托幼机构传染病疫情报告规范的通知（2006）](https://www.moe.gov.cn/srcsite/A17/moe_943/s3285/200604/t20060406_81035.html)：历史全国学校报告框架，支撑校内发现与报告职责链的教学设计。
- [国家卫生健康部门公开说明：学校传染病疫情发现、登记、报告制度](https://www.nhc.gov.cn/zwgk/jdjd/201304/149f62864b304f9fb8aaa507d18d60d4.shtml)：班主任、学校疫情报告人及领导之间的职责衔接。
- [武汉市学校传染病防控有关规定（2025，地方示例）](https://wjw.wuhan.gov.cn/zwgk_28/zc/gfxwj/202509/t20250917_2648818.shtml)：早发现、报告及处置协同的地方实施参考。

页面采用通用处置任务，所在地现行流程与学校预案决定实际职责及要求。教师角色保持教育沟通、观察、报告和协同职责，医学判断及停复课决定由对应专业人员和责任机构处理。

## 用户验收入口

新建一次训练，依次查看处置台、填写并修订、继续角色对话、进入方案/评价、查看复盘和事件中心；使用另一个账号核对数据隔离。此清单供用户执行，功能、浏览器与模型验收结果待用户反馈。编译和发布健康结果在交付报告单独记录。
